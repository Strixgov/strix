<strix-verify>

One-line embeddable verification card for Strix-governed AI agent evidence. Drop it on any HTTPS page. WebCrypto Ed25519 runs in the visitor's browser. No Strix backend in the trust path.

Quick start

Two tags, anywhere on the page:

<script src="https://verify.strixgov.com/embed.js"></script>
<strix-verify evidence-id="5686"></strix-verify>

The element fetches the evidence record from the public proof API, resolves the signing key from the public JWKS, runs Ed25519 verification client-side, and renders a self-contained card. Works in any modern browser (Chrome, Firefox, Safari, Edge). Bundle size: ~8.6 KB gzipped.

Live demo — verified record

<strix-verify evidence-id="5686">

Live demo — compact mode

<strix-verify evidence-id="5686" compact>

Attributes

Attribute Required Notes
evidence-id yes The evidence record ID to verify. Numeric or string.
compact — Boolean attribute. Renders a smaller card; hides the details block.
proof-base — Override the proof API base URL. Defaults to https://www.strixgov.com. Used for forks + testing.
jwks-url — Override the JWKS URL. Defaults to the canonical Strix JWKS endpoint. Used for forks + testing.
auto-refresh — Milliseconds between re-verifications. Minimum 30000 (30s). Useful for live dashboards.

Programmatic API

The element exposes a verifyNow() method and dispatches a strix-verify:result custom event:

const el = document.querySelector('strix-verify');

// Trigger a verification (returns the result object directly)
const result = await el.verifyNow();
console.log(result.verificationStatus);
// → "VERIFIED" | "COMPLIANCE_VIOLATION" | "UNSIGNED" |
//   "LEGACY_UNSIGNED" | "NOT_FOUND" | "ERROR"

// Or listen for results bubbling out of the shadow tree:
el.addEventListener('strix-verify:result', (e) => {
  console.log(e.detail);
});

Why this exists

The trust model. Strix produces Ed25519-signed receipts for every governed agent action. The receipts are independently verifiable — anyone with the public JWKS can confirm that a specific action happened, was approved, and hasn't been tampered with, without trusting Strix's infrastructure at all.

Until now, that verification required either the Node CLI (npx @strixgov/verifier@latest <id>) or visiting verify.strixgov.com. The embed makes it a one-line drop-in — so any framework, blog post, audit report, or compliance dashboard can show verified Strix evidence inline.

What you're embedding. A WebCrypto Ed25519 verifier that talks only to the public proof API and the public JWKS. No accounts, no API keys, no tracking. The bundle is MIT-licensed and the source is on the public Strixgov/strix mirror.

Styling + customization

The card lives in a Shadow DOM so the host page's CSS can't change its layout. To re-theme, override CSS custom properties on the element:

strix-verify {
  --sv-bg: #ffffff;        /* card background */
  --sv-surface: #f7f7f9;
  --sv-fg: #1a1a1a;
  --sv-accent: #5b8def;
  --sv-verified: #1f7e3d;  /* override the "VERIFIED" green */
}

Versioning + provenance

The bundle served at verify.strixgov.com/embed.js is built from the public @strixgov/verify-embed package. It uses the same byte-for-byte canonical reconstruction as @strixgov/verifier — a mirror-invariant test in the package's test suite enforces it.

If you're integrating into a production system, pin the version by installing from npm instead of using the CDN:

npm install @strixgov/verify-embed
